Diagrama de classes UML – Venda de produtos por cupom fiscal

9 entidades JPA, 1 classe embutida (Endereco) e 1 enum. Venda é o cupom fiscal; ItemVenda é a entidade intermediária entre Venda e Produto. Herança Pessoa → Cliente/Funcionario (JOINED).

direction LR
class Pessoa {
  <<abstract>>
  -Long id
  -String nome
  -String cpf
  -Endereco endereco
}
class Cliente
class Funcionario {
  -String matricula
}
class CartaoFidelidade {
  -Long id
  -String numero
  -LocalDate dataEmissao
}
class Endereco {
  <<Embeddable>>
  -String logradouro
  -String cidade
  -String estado
}
class Loja {
  -Long id
  -String nome
  -Endereco endereco
}
class Categoria {
  -Long id
  -String nome
}
class Produto {
  -Long id
  -String nome
  -BigDecimal preco
}
class Venda {
  -Long id
  -LocalDateTime dataHora
  -FormaPagamento formaPagamento
  +adicionarItem(Produto, int)
  +getTotal() BigDecimal
}
class ItemVenda {
  -Long id
  -int quantidade
  -BigDecimal precoUnitario
  +getSubtotal() BigDecimal
}
class FormaPagamento {
  <<enumeration>>
  DINHEIRO
  DEBITO
  CREDITO
  PIX
}
Pessoa <|-- Cliente
Pessoa <|-- Funcionario
Pessoa *-- Endereco
Loja *-- Endereco
Cliente "1" --> "0..1" CartaoFidelidade : cartao - OneToOne
Produto "*" --> "1" Categoria : categoria
Venda "*" --> "1" Cliente : cliente
Venda "*" --> "1" Loja : loja
Venda "*" --> "1" Funcionario : operador
Venda --> FormaPagamento
Venda "1" *-- "1..*" ItemVenda : itens / venda - bidirecional
ItemVenda "*" --> "1" Produto : produto

Modelo relacional OLTP (PostgreSQL)

9 tabelas. cliente.id e funcionario.id são PK e FK para pessoa.id (herança JOINED). item_venda resolve o N:N entre venda e produto. Script: sql/oltp/01_ddl_oltp.sql.
